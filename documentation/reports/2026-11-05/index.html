Summary#

This week in one paragraph

A. Adiga asked that the framework run a stated hypothesis and report whether it holds, instead of searching until something improves. That protocol now exists. The 2024-25 season is held out, the hypothesis and the test were committed before any 2024-25 forecast existed, and a paired test treats each forecast date as one observation. The first hypothesis tested is the best in-sample finding so far, and it fails: emphasis on peak-phase training rows, used for 1-2 week forecasts only, changes 2024-25 peak WIS by -0.19 (p = 0.99). The reason is consistent across seeds: the 1-week gain replicates, the 2-week gain reverses. Even in-sample the gain is not significant (p = 0.13). The point estimates the project acted on so far are inside the noise of a per-date test.

The framework in one page: what connects to what, the commands for every step, and a real run made on 2026-11-05. The full reference is PROJECT_OVERVIEW.md.

Four steps, numbered in the boxes. 1 picks a model family, 2 is the agent loop that refines it, 3 runs controlled experiments outside the agent, and 4 tests whether an experiment's gain is real. How to read this run

The mechanics and guardrails work: each action was validated before it was applied, and an invented citation ("iter 1") was dropped. The 15% gain is not evidence: improve scores one cutoff and one seed, and 2025-12-06 is in the surge, where peak emphasis is known to help. Across 9 cutoffs and 3 seeds, round 2 found this kind of change worse on peak WIS. The agent saw that result and still proposed it: all four round 2 entries for this action were in its retrieved facts. In iteration 1 it cited two older entries about calendar-phase weights, a different action from the one it chose. This is the case for gating the loop's accept rule with the significance test.

Held-out result#

Hypothesis H1. Peak-phase training rows copied 5 times (oversample_5), used for 1-2 week forecasts with baseline forecasts for 3-4 weeks, lower peak-phase WIS on 2024-25. The unit is the forecast date, because rows from one fit are correlated; each date's value is scaled so that the mean over dates equals the pooled peak WIS difference, then averaged over seeds 42, 43 and 44. Caveats

Power is low: 11 peak forecast dates, so "not confirmed" is not evidence of no effect. 2024-25 is a harder season: baseline peak WIS is about 3 times the 2025-26 value, and the baseline under-predicts the peak by about 440 admissions per row. The base hyperparameters may have been tuned with a cutoff inside 2024-25; both arms share them. WIS uses 5 quantiles, so absolute values are not comparable with FluSight.

Related work#

TimeSeriesScientist (arXiv 2510.01538)

no rigor

Four LLM agents in one pass pick 3 of 21 models, tune them on validation MAPE and ensemble them. No seeds, variance or tests, point forecasts only, no knowledge bank. On ILI, Prophet has about half its MAE. Its missing control (a plain search over its own library) is one our paper also needs.

Hypothesis learning (arXiv 2112.06649)

template

Competing hypotheses act as mean functions of a structured Gaussian process; a variance-reduction reward picks the next experiment. It ranks hypotheses by reward and computes no posterior and no significance: a template for our loop, not a ready method.

ERA (arXiv 2605.16238)

competitor

LLM tree search over forecasting pipelines, first in the CDC 2025-26 evaluation. Our claim is rigor and interpretability with an in-house model, not leaderboard rank.

POPPER (arXiv 2502.09858)

design option

LLM agents falsify hypotheses with sequential e-value tests: a way to control error across many hypotheses inside an agent loop.

Decisions requested#

What gates the agent's accept decision: the paired test or a posterior?

The Diebold-Mariano test exists and is tested. A conjugate Bayesian posterior over competing hypotheses can run on saved forecasts without retraining. Recommendation: the test first, the posterior next.

Test "emphasis on 1-week only" on 2023-24?

It was formed after seeing 2024-25, so it needs an unused season. 2023-24 is the only one left, and its models would train on less than 2 years of history. Recommendation: run it, labelled post hoc.

Is the forecast date the right unit of analysis?

Per date and per season (current), or pool dates across seasons for power. Recommendation: keep per-date; pool only hypotheses fixed before either season was seen.

Does October count as off-season?

The adiga_2026_10 scheme treats October as off-season by assumption. It changes which rows count as growth.
